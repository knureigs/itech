Лабораторна робота №5

Публікація власного web-ресурсу
5.1 Мета роботи
Закріплення практичних навичок розробки веб-ресурсів з використанням HTML та CSS, набуття досвіду проектування структури та інтерфейсу сайту, підготовки технічного завдання, організації вихідного коду у системі контролю версій та публікації готового ресурсу у мережі Інтернет.
5.2 Необхідні засоби
Для виконання лабораторної роботи рекомендується використовувати таке відкрите програмне забезпечення:
  • редактор коду MS Visual Studio Code або будь-який інший, який знайомий користувачу і забезпечує підсвічування синтаксису (Notepad++, Sublime Text, Atom, Brackets и т.п.);
  • браузер Mozilla Firefox або Google Chrome;
  • СКВ Git (для роботи з сервісом GitHub потрібен доступ до мережі Інтернет).
5.3 Порядок виконання роботи
  1. Обрати тематику ресурсу. На свій розсуд, примусового розподілу не передбачено. Ресурс може бути присвячений рідному місту, улюбленому фільму, серіалу, анімації, книзі, напрямку у музиці, письменнику тощо. Єдина вимога - обрана вами тематика та плануємий контент не повинні порушувати чинного законодавства та загальних культурних норм. Пам'ятайте, що ваші роботи і звіти зберігаються в університеті тривалий час і доступні керівництву.
  2. Опис технічного завдання у файлі README.md. ТЗ має довільний формат, і зазвичай передбачає висвітлення наступних питань:
    • загальні відомості про ресурс (назва (якщо вона передбачається) та короткий опис призначення ресурсу);
    • цільова аудиторія (для кого призначений сайт);
    • функціональні вимоги (які можливості має надавати ресурс);
    • структура сайту (перелік сторінок (якщо ресурс багатосторінковий) та їх призначення);
    • вимоги до дизайну (кольорова гама, шрифти, загальні побажання щодо оформлення);
    • технічні вимоги (використані технології, вимоги щодо адаптивності, підтримувані браузери);
    • використані зовнішні матеріали (зображення, тексти, графіка) та їх джерела.
  3. При реалізації пам'ятати про забезпечення адаптивності. Перевірити роботу у різних браузерах при різному розмірі вікна.
  4. При розміщенні вихідного коду у репозиторії на Github обрати ліцензію. Я раджу MIT, але розгляньте і інші варіанти.
  5. Скористатися сервісом Github Pages (як вже робили на першій лабораторній, присвяченій HTML).
  6. Перевірити створений ресурс на валідність за допомогою онлайн-сервісу, в якому використовувати URL-адресу опублікованого на Github Pages документа. Виправити помилки, які не пов'язані з використанням CSS.
  7. Перевірити створений ресурс за допомогою PageSpeed Insights, в якому використовувати URL-адресу опублікованого на Github Pages документа. У звіті навести фрагмент висновків, принаймні, щодо показників First Contentful Paint та Largest Contentful Paint.
  8. Перевірити доступність створеного ресурсу за допомогою сервісу WAVE, в якому використовувати URL-адресу опублікованого на Github Pages документа.
  9. Бути готовим до запитань стосовно вашого коду.

Відпрацювання може бути отримано шляхом демонстрації студентом повністю виконаної роботи викладачу, з відповідями на запитання викладача щодо ходу роботи та використаних засобів. Можливий запит щодо отримання викладачем посилання на GitHub репозиторій проекту з кодом лабораторної роботи.
5.4 Зміст звіту
Формальний звіт з лабораторної роботи повинен містити: мету роботи, розроблене ТЗ, вихідний код web-сторінки та стильових файлів, зображення ресурсу, посилання на репозиторій, скріншоти валідатора, формальні висновки по роботі.
